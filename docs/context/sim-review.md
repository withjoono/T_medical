# 복기 카드 · 질문 없는 방 · 지난 수업 과제 (2026-11-19)

사용자 지시: 경쟁 학원(소도스카이) 서울대 의대 면접반을 분석한 뒤 "참고할 장치 1·2·3 을 구현하라. 구현 뒤 서울대 면접 페이지에 자세히 설명하라."
분석 원문은 Claude 프로젝트 문서 `claude/sodosky-snu-interview-analysis-2026-11-19.md`.

모의면접 한 번을 **응시 → 복기 → (수업) → 다시 답하기** 한 묶음으로 만든다. 셋 다 "선생님 수업에 가져갈 재료"를 남기는 장치다 — AI 가 고쳐 주는 기능이 아니다.

## 무엇이 들어왔나

| 장치 | 언제 | 하는 일 |
|---|---|---|
| 질문 없는 방 | 면접실 첫 30~40초 | 면접관 첫 질문을 가려 두고, 제시문에서 쟁점과 예상 질문 두 가지를 먼저 말한다. 결과 화면에 예상한 것과 실제 질문을 나란히 놓는다 |
| 방 복기 카드 | 방을 마친 직후, 점검 결과를 보기 전(점검이 도는 10~30초 동안) | 가장 막힌 질문 · 결론 한 줄 · 바꿀 한 가지 · 기준별 자기 판단(해냈다/애매하다/못 했다). 결과 화면이 내 판단과 점검을 나란히 놓고 엇갈린 기준을 짚는다. '복기 요약 복사'로 선생님께 보낸다 |
| 지난 수업 과제 | 수업 뒤, 다음 모의면접의 첫 문항 | 결과 화면에서 "수업에서 선생님이 짚은 문항"으로 표시하고 선생님 말씀을 한 줄 적는다. 다음에 시작 버튼을 누르면 그 문항을 다시 답하는 연습 회차가 먼저 열리고, 지난 점검과 이번 점검을 기준별로 나란히 보여 준 뒤 원래 하려던 회차로 이어진다 |

## 모든 대학으로 확대 (2026-11-19 같은 날, 사용자 "모든 대학으로 확대해줘")

- **페이지 설명** — 의치한약수 대학 면접 페이지 77곳에 `#ai-loop` 절을 넣었다(서울대 의대는 위 `SNU_MED.aiLoop` 그대로). 문장 SSOT 는 `lib/ai-homework.ts`, 그리는 곳은 `app/interview/_ai-homework.tsx`(마운트 뒤에만 — 같은 본문이 수십 페이지 정적 HTML 에 깔리지 않게, `_class-story.tsx` 와 같은 원칙). 제목·부제만 대학마다 서버가 그린다.
  - 형식별(ClassKind): 생기부·서류 58곳 = ② 복기 카드 · ③ 과제 두 단계(공통 문항을 낼 수 없어 ① 을 뺐다) / MMI 10곳 · 제시문 8곳 = ① 질문 먼저 짐작하기(연습에서 선택) + ② + ③.
  - **가천대(의예·약학)는 넣지 않았다** — 수업에 AI 모의면접이 없다(business-decisions.md 가천대 예외). 가천대 AI 세트가 수업에 붙으면 `homeworkLoop("concept")` 를 채운다.
  - 서울대 의대의 ② ③ 문장도 같은 SSOT 를 쓴다(`REVIEW_STEP`·`TASK_STEP`).
- **화면(모의면접)** — 복기 카드·과제는 처음부터 모든 형식에서 작동했다. 질문 가리기는 모든 형식의 연습에서 켤 수 있고, 이름이 다르다: 질문을 실제로 주지 않는 서울대 의예 = '질문 없는 방'(기본 켜짐·실전 포함), 나머지 = '질문 먼저 짐작하기'(기본 꺼짐·연습만). `isQuestionless(univ, track)` 이 서울대 치의·수의·약학·간호를 뺀다(질문 없음 근거가 의예뿐).
- **실전에는 넓히지 않았다** — 질문이 주어지는 대학의 실전에서 질문을 가리면 대학 형식이 아니게 되고, 실전 기록으로 매기는 등수(mock-sets.md)의 조건이 섞인다. 바꾸려면 등수 규칙부터 정한다.

## 지킬 것

1. **고치는 주체는 선생님이다.** 화면은 학생의 판단과 점검 결과를 나란히 놓기만 한다. "AI 가 교정한다·채점한다"로 읽히는 문구 금지(business-decisions.md). 과제 전후 비교도 "달라졌는지만 보여 주고, 고쳐졌는지는 선생님이 확인"이라고 적는다.
2. **질문 예상은 채점하지 않는다.** 역량을 새로 만들지 않는다 — 서울대 모의면접 등수 비교(mock-sets.md)를 흔들지 않기 위해서다. 서버로 옮기더라도 '독해·요지'의 근거로만 쓴다.
3. **예상한 내용은 서버로 보내지 않는다.** `/turns` 로 보내면 답변으로 처리되어 꼬리질문이 하나 줄어든다. 예상 단계에서 방이 끝나도 초안을 답변으로 보내지 않는다.
4. **질문 없는 방의 적용 범위.** 질문 없이 제시문만 주는 것으로 확인된 대학(`isQuestionless` — 지금은 서울대뿐, 근거 `lib/gichul-data/snu.json`)은 실전·연습 모두 기본으로 켠다. 그 밖의 대학은 **연습에서만** 학생이 켤 수 있고, 실전은 대학 형식 그대로 둔다. 대학을 추가하려면 근거를 먼저 적는다(data-rules.md '실측만').
5. **과제 회차는 질문 없는 방을 끄고, 다시 과제로 정할 수 없다.** 질문을 이미 아는 문항이기 때문이다. 과제 때문에 먼저 여는 것은 '아직 한 번도 다시 답하지 않은 과제'뿐이다(학생이 건너뛸 수 있다).
6. **복기 카드는 점검 결과를 보기 전에만 쓴다.** 결과를 본 뒤 자기 판단을 받으면 의미가 없다 — 나중에 채워 넣는 길을 만들지 않았다.

## 넣지 않은 것 — 다시 넣지 말 것

- **"수업 후 1시간 안에 해설지 복습"**(소도의 규칙)을 옮긴 '해설 열람 + 1시간 내 같은 문항 재답변 + AI 전후 비교'는 사용자와 검토해 뺐다(2026-11-19). 이유: ① 그 규칙은 기록이 남지 않는 대면 수업의 휘발성을 막는 장치인데 T메디는 대화 기록과 복기 카드가 남는다 ② 해설을 본 직후의 재답변은 거의 항상 좋아진 것처럼 나와 '외운 티 나는 답'을 만든다(interview-2session-curriculum.md 가 경계하는 것) ③ AI 가 해설을 주고 전후를 재면 교정의 주체가 흐려진다 ④ 문항마다 해설을 쓰고 검수해야 한다. 남긴 것은 "고친 것을 다시 해 본다" 하나이고, 시점을 **선생님 수업 뒤**로 옮겨 '지난 수업 과제'가 됐다.
- 모범답안·해설은 주지 않는다(기존 방침 그대로).

## 저장 — 지금은 이 브라우저에만

- `localStorage` 키 `medical_sim_review:<Hub 사용자 id>`(계정별). 복기·회차 설정은 150일 뒤 정리, 과제는 끝내거나 지울 때까지.
- 서버 기록을 지우면(한 건·전체) 그 회차의 복기와 그 회차에서 정한 과제도 함께 지운다.
- **한계(페이지에도 적었다):** 다른 기기에서는 복기·과제가 보이지 않는다. 선생님은 선생님앱에서 이 내용을 볼 수 없다 — 학생이 '복기 요약 복사'로 보내거나 수업 중 화면을 공유한다. 과제도 선생님이 직접 지정하지 못하고 학생이 받아 적는다.

## 서버(susi-back `/interview-sim`)로 옮길 때 — 이 리포 밖, 아직 안 함

2026-11-19 작업 세션에서는 Susi 리포에 접근하지 못해 화면만 만들었다. 서버에 받는 곳이 생기면 `lib/sim-review.ts` 의 읽기·쓰기만 바꾸면 된다(화면은 그대로).

1. 복기 저장 — 방마다 `{ prediction, hardest, conclusion, redo, self }`. 선생님앱의 학생 기록 화면에 엇갈린 기준(`gaps` 와 같은 규칙)을 먼저 띄운다.
2. 선생님이 과제를 직접 지정 — 선생님앱에서 문항 + 한 줄 조언 → 학생 첫 화면의 과제 카드. 지금의 학생 입력은 그때까지의 다리다.
3. 질문 없는 방을 회차 옵션으로 — 서버가 알면 예상을 받아 '독해·요지' 근거로 쓸 수 있다(채점 역량은 늘리지 않는다).
4. **추가 제시문** — 꼬리질문 3회 중 한 번을, 학생이 고른 입장과 부딪히는 짧은 글로 바꾼다(서울대 후기: 첫 해석 뒤 반대 방향의 추가 제시문). 문항마다 입장별 글 두 벌이 필요하고(`lib/mock-sets/snu-mmi.ts` 에 칸을 더해 선생님 검수), 꼬리질문 생성 쪽이 그것을 쓰도록 고쳐야 한다. **화면에 없으므로 페이지에 적지 않았다.**
5. 확인 필요 — 실전 회차에서 정한 과제는 `start({ mode: "practice", promptId, roomIdx })` 로 연다. 서버가 400 을 주면 `promptId` 만으로 한 번 더 시도한다. 실제 서버에서 두 경우 모두 그 문항이 열리는지는 확인하지 못했다.
6. 서울대 형식(자체 제작 세트)이 서버에 등록되어야 서울대 지원자에게 '질문 없는 방 기본 켜짐'이 실제로 보인다(mock-sets.md '남은 일'). 그 전까지는 열려 있는 형식의 연습에서 학생이 직접 켠다.

## 검증 (2026-11-19)

- `tsc --noEmit` 통과(공통 헤더 패키지는 스텁).
- jsdom + 가짜 서버로 화면 흐름을 끝까지 돌려 48개 항목 확인 — 기본값, 예상 단계에서 질문이 가려지는지, 예상이 서버로 가지 않는지, 점검 중 복기 카드와 저장 버튼 잠금, 엇갈림 표시('보류' 제외), 요약 복사(답변 원문 없음), 과제 표시 → 과제 먼저 → 전후 비교 → 이어서 실전, 기록 삭제 시 함께 지우기. 검증 스크립트는 리포에 넣지 않았다(jsdom·testing-library 의존성을 늘리지 않으려고).
- **하지 못한 것:** 실제 서버·실제 브라우저(음성 인식 포함)에서의 확인, 화면 모양 눈 확인. 로그인이 필요한 화면이라 원격 세션에서 열 수 없었다.
