# 데이터 원칙·원천·필터

## 1. 게시 원칙 — 데이터 완결성보다 우선

- **실측만 싣는다.** 입결컷 원본의 `자료출처` 는 `입결+어디가`(실측)와 `추정(계열)` 로 나뉜다.
  추정치는 `lib/ipkyul/*.ts` 에 **아예 넣지 않는다.** cut 이 없는 전형은 `—`/'공시 입결 없음'으로 비운다.
  의대는 1.2와 1.4가 당락을 가르므로 계열 평균을 입결로 내보내면 오지원을 만든다.
  - 빌드 산출물에 `추정(계열)` 문자열이 0건인지 확인한다.
  - `예상컷(yesangcut_*)`·`합불(hapbul_*)` 을 쓰게 되면 '입결'이 아니라 **'예상 합격선(추정)'** 으로 이름과 섹션을 분리한다.
- **요강이 밝히지 않은 값은 `요강 미기재`** 로 남긴다. 추정해서 채우지 않는다.
- 확정 날짜가 없으면 `announce: null` + `announceAssumed` + `announceNote`(근거) — 페이지가 "미공지 / (예정)"으로 표기한다.
- 대학별 수치(논술 실시 대학, 최저 기준)는 출처마다 집계가 달라 단정하지 않는다. "최종 모집요강 기준" 문구를 유지한다.
- 수치를 고치면 각 페이지 하단 `SourceNote`·`sources` 의 **기준 시점·출처도 함께** 고친다.
- 선생님 경력은 `lib/teachers.ts` 에 등록된 credential 만 노출한다. 코드가 경력을 지어내지 않는다.

## 3. 계열 필터 규칙 (`unit.csv`)

이름 정규식만 쓰면 `전 모집단위(… 의예과 …)` 같은 열거형 행 2,081개가 섞여 의예 인원이 16,584명으로 부푼다.
**`소계열` + 이름 + 열거형 배제** 를 함께 건다.

| 계열 | 소계열 | 이름 포함 | 제외 |
|---|---|---|---|
| uiye | `의학` | 의예\|의학과\|의학부 | 한의\|수의 |
| chiuiye | `치의학` | 치의예\|치의학 | |
| hanuiye | `한의학` | 한의예\|한의학 | |
| suuiye | `동물ㆍ수의학` | 수의예\|수의학 | |
| yakhak | `약학` | 약학 | 한약 |

- 열거형 배제 = 모집단위명 30자 초과 또는 `전 모집단위|통합모집|자율전공|자유전공` 포함
- 수동 보정: 부산대 한의학전문대학원 학·석사통합과정(소계열 `의학` 오분류) → 한의예로 편입
- 수능최저는 **전형 단위 텍스트**라 다른 학과 안내가 섞여 있다. `app/ipkyul/_ipkyul.tsx` `pickMinimum()` 이
  **그 행의 모집단위명에서 키워드를 뽑아** 해당 문장만 남긴다. 고정 키워드 목록을 쓰면 `혁신신약학과` 가 `약학` 에 걸린다.
- 다계열 합산 행(대구가톨릭대 `지역교과 (의예과, 약학부)`, 인제대 `의예·약학`)은 `quotaByType` 합계에서 빼고 "타 계열 합산"으로 표시한다.

## 4. 면접 분류 — 두 축, 그리고 대학이 진입 단위

- **질문 출처(source)** 생기부/제시문/현장 문항 과 **평가 배점(scoring)** 인성·적성 비율/역량 비율 은 서로 다른 축이다. 한 대학이 둘 다일 수 있다. 하나로 묶지 말 것(`lib/field-interview.ts`).
- 방문자가 아는 것은 **지원 대학 이름**이다. 허브의 진입 단위는 유형이 아니라 대학(대학 그리드 + 한눈에 표, 면접일 빠른 순, 미공지는 맨 아래).
- 한눈에 표 칼럼 순서: 대학 · 권역 · 방식 · 면접 전형 · 1차 발표 · 면접일. 1차 발표는 가장 이른 면접 전형 기준, 수능 전 면접에는 `수능 전` 표시.
- 분류 근거는 각 대학 `format[]` 의 요강 문장. **요강이 "MMI 아님"이라고 못박은 대학은 면접실이 둘이어도 mmi 로 넣지 않는다**(동아대·한양대·연세대).
- **MMI는 의예과에만 있다**(2027 전수 확인). 치의예·한의예·약학·수의예에는 없다. 을지대는 2028부터 MMI 예고.
- 강원대는 2027부터 MMI 폐지(확인 면접 1실, `style: "none"`). 고려대 학업우수전형은 2027 면접 미실시. 면접 미실시 의대: 가톨릭관동대·충북대.
- 생기부·서류확인형은 인·적성에 통합(질문 출처가 생기부라 준비법이 같다).

## 4-1. 공개 면접 기출 — 선행학습 영향평가 보고서 (2026-10-28)

- 대학이 매년 3월 공개하는 「선행학습 영향평가 자체평가 보고서」의 면접 질문 사례가 원천이다. 가천대는 `lib/gachon-gichul.ts`, 나머지 대학은 `lib/univ-gichul.ts` + `lib/gichul-data/<key>.json`(대학당 파일 하나, 목록 `index.ts`).
- 대학별 데이터는 보고서 원문을 다시 받아 문항마다 대조한 **검수본**만 싣는다. 한 번 더 공개용 문구 정리(작업 용어·수집 경위 제거)를 거친다. 2026-10-29 첫 반영 35개 대학.
- `unit` 은 보고서가 공개한 범위 그대로다 — `전 계열 공통` 예시를 '○○대 의대 기출'로 쓰지 않는다. 재외국민·정시 전형 문항은 `topic` 앞에 전형을 붙여 수시 기출처럼 보이지 않게 한다.
- 가이드북 예시(경북대 학종 등)는 출제 학년도가 아니다 — `src` 에 '가이드북'을 넣으면 카드가 'YYYY 가이드북 예시'로 표시한다. 기출이 없고 대학이 예시문항만 공개한 곳은 `examples`(블록에 '기출 아님' 표시).
- 같은 대학 여러 계열 페이지의 공통 블록(한마디·비교표·인성 표·준비 순서) 배치는 `gichulLayout()` 한 곳이 정한다. 사이트에 없는 계열 페이지(예: 동국대 WISE 한의대)는 데이터에서 뺀다.
- 보고서·입학처 문항 PDF 에 '상업적 사용 금지'·'변형·발췌 금지' 문구가 있는 대학이 있다(부산대·성균관대·건국대·연세대·연세대 미래 보고서, 서울대 입학본부 기출 PDF). 원문을 옮기지 않고 요약·분석·출처 표기로 싣는 방식으로 **사용자가 게시를 결정했다**(2026-10-29). 원문 문장을 그대로 길게 옮기는 것은 여전히 금지.
- 보고서 예시답안이 틀린 경우가 있다(인제대 2026 재외국민 상평형·세포 호흡). 옮기지 말고 맞는 답을 싣되 보고서와 다르다고 카드에 밝힌다.
- 가천대 보고서의 '의약계열' 표(2025·2026 각 5문항) = 가천의약학(의예·한의예·약학) 기출. '인성관련' 5문항씩은 계열 공통.
- 보고서는 의예·한의예·약학을 **나누지 않는다.** 어느 학과 질문인지 지어내지 말 것 — 세 페이지 배치(생명·의료 → 의대, 화학 → 약대, 수학·윤리·인성 → 한의대)는 과목 성격에 따른 배치일 뿐이고 페이지에도 그렇게 밝힌다.
- **세 페이지에 같은 문항을 겹쳐 싣지 않는다**(2026-10-24 중복 제거 원칙). 각 페이지는 자기 몫만 싣고 나머지 두 페이지로 링크한다.
- 질문은 보고서 문장을 그대로 옮기지 않고 '근거 기록 + 묻는 것' 으로 요약한다.
- 가천대 한의예과는 2027학년도 면접 미실시(논술·교과)라 한의대 페이지에는 "2026학년도까지 한의예과도 본 기출" 안내를 붙였다.

### 4-2. AI 모의면접 세트 — 기출에서 만든다 (2026-10-29)

`/interview/ai` 의 학과 → 대학 → 전형 선택기는 위 기출 데이터로 만든 **면접 세트**를 코치에 넘긴다(규격: Interview `docs/interview-set-spec.md`).
변환은 `lib/interview-sets.ts` 하나, 공개 파일은 `scripts/build-interview-sets.ts` 가 빌드 때 `public/interview-sets/` 에 만든다(gitignore).

- 학과 세트에 넣는 범위: 그 학과 단위(의예과 등) · `전 계열 공통…` · `의약계열(학과 구분 없음)`. **`자연계열 공통` 은 넣지 않고 페이지 배치(page)를 따른다** —
  서울대 수학 구술처럼 공대·약대 등 전형에 적힌 모집단위만 함께 쓰는 문항이라 의대 면접과 다르다. `의예과 외 학과` 는 의대에 넣지 않는다.
- 전형별로 묶는다. 국내 수시 전형이 둘 이상이면 '수시 전형 전체' 묶음을 앞에 둔다. 재외국민·외국인 전형과 '정시'만 적힌 전형은 거기 섞지 않고 뒤에 둔다
  ('수시·정시 통합 공개'는 수시로 본다).
- 대학이 질문을 공개하지 않은 제시문 문항(31개)은 "대학이 질문은 공개하지 않았습니다. 제시문을 읽고 핵심 쟁점과 본인의 판단을 말해 보세요."로 연습한다 — 질문을 지어내지 않는다.
- 답변 시간은 대학이 밝히지 않았으므로 넣지 않는다(코치 기본값). 가천대 한의예과는 2027 면접이 없어 세트를 만들지 않는다.
- 세트 검사기(`lib/interview-set/`)는 Interview 저장소 복사본이다. 직접 고치지 말고 Interview 에서 `node tools/sync-coach-to-tmedi.mjs` 로 다시 받는다.
- 문항 아래 `basis` 에 붙는 라벨은 종류(kind)로 정한다(2026-11-19) — 제시문·MMI 상황 → 「제시문·상황 요지」, 공통문항·`…(기출 아님)` → 「문항 설명」, 그 밖 → 「생기부 기록」.
  대학 페이지(`_univ-gichul.tsx` `basisLabel`)의 제시문·상황 / 배경 / 근거 기록과 같은 구분이다. 그전에는 공통문항에 「제시문·상황 요지」가 붙어, 제시문이 없는 면접(이화여대 등)이 제시문 면접처럼 보였다.
  공통문항 83개(18개 대학)의 `basis` 를 확인했다 — 70개는 "특정 기록 인용 없음" 같은 설명뿐이고, 13개(인하대 재외국민 5 · 인제대 재외국민 7 · 강원대 치의예 1)는 같은 문장에 문제의 조건·상황이 함께 적혀 있다. 둘을 가르는 표시가 데이터에 없어 라벨은 「문항 설명」 하나로 둔다.

#### 예외 — 응시 후기로 진행을 맞춘 대학 (이화여대, 2026-11-19 소유자 승인)

위의 「답변 시간은 대학이 밝힌 값만」·「질문을 지어내지 않는다」의 예외는 `lib/interview-sets.ts` 의 `REVIEW_FLOW` 하나다. 지금은 이화여대뿐이다.

- **왜**: 이화여대 미래인재전형-면접형은 요강에 면접 시간·면접위원 수·진행 순서가 없다. 면접(11/22)을 사흘 앞두고, 3문항 · 90초로 도는 기본 세트가 실제 진행(6분 안팎에 6~7문항)과 너무 달라 연습이 되지 않았다. 같은 전형의 2026학년도 응시 후기 2건이 진행을 구체적으로 적어 두어 그 진행에 맞췄다.
- **무엇을**: 이대 세트 8개(의대·약대 × 전형 묶음 4)는 기본 6문항 · 문항당 60초(`rooms[0].answerSec`), 순서는 지원동기 → 생기부 기반 4개 → 마지막으로 하고 싶은 말. 지원동기·마지막 한마디 두 문항은 후기에서 왔다.
- **근거**: 울산광역시교육청 울산진로진학지원센터 「2026 대입 면접 후기 자료집」의 미래인재전형-면접형 후기 2건(수학교육과·과학교육과 — **약학부·의예과 후기가 아니다**). 면접관 3명이 돌아가며 질문, 6분 안팎·타이머(한 건은 종료 1분 전에 울림), 블라인드라 자기소개 생략(한 건), 지원동기 → 세특·창체 기반 질문 4~5개 → 마지막으로 하고 싶은 말, 한 건은 꼬리질문 없음. 수시 저장소 `interview-reviews.json` 에 같은 후기가 있다.
- **섞어 표기하지 않는다**: 후기에서 온 두 문항은 `meta.kind` '응시 후기' · `scope` '대학 공개 문항 아님' · `passages` 라벨 「출처」로 따로 적고, 세트 `notes` · `source.label` · 선택기 안내(`PickerEntry.note`)에도 밝힌다. `timeNote` 에는 "대학은 면접 시간을 밝히지 않았고 2026 응시 후기에 맞춘 연습용 시간"이라고 적는다. 대학 공개 문항은 전 계열 공통 예시뿐이라는 것도 `notes` 에 적는다 — 약학부·의예과 전용 기출처럼 쓰지 않는다.
- **코치 동작**(2026-11-19 tmedi.kr 배포본 `assets/embed-27tqfiRp.js` 에서 확인): question 엔진은 `rooms[0].answerSec` 를 「답변 제한 시간」(문항당) 기본값으로 쓰고, `pick: 'student'` 이면 문항 목록 **앞에서부터** `itemsPerRoom` 개를 골라 둔다. 그래서 문항 순서가 곧 기본 연습 순서다. 학생이 문항을 더 고르면 「마지막으로 하고 싶은 말」 뒤에 붙는다(코치에 순서 지정이 없다).
- **대학 페이지에 적는 값도 출처를 나눈다**: 면접관 3명 · 평가 비율 학업역량 30 · 진로역량 40 · 발전가능성 30 은 입학처 설명을 인용한 보도(베리타스알파 2026-06-15 · 2026-11-17)이고 요강에는 없다. 면접 시간은 대학 미공개 / 2026 후기 6분 안팎 / 세종시교육청 대입지원단 「2027학년도 대입 수시모집 면접전형 자료집」 면접위원 2~3명 · 10분 내외 — 서로 다르므로 하나로 정하지 않고 나란히 적는다. 요강 문장만 싣는 `format[]` 에는 넣지 않고 `notes` · `scoring.detail` 에 둔다.
- 다른 대학에 같은 예외를 두려면 ① 같은 전형의 후기인지 ② 어느 모집단위 후기인지 ③ 대학이 밝힌 값과 어긋나지 않는지 확인하고, 이 절에 대학과 근거를 추가한다.

## 4-2. 계열별 기출 분석 분리 — `byField` (2026-11-09)

- 같은 대학이라도 계열마다 면접이 전혀 다르면(서울대: 의예 제시문 면접실 + 생기부 / 약학 수학 구술 / 수의 생명과학 상황 면접) 대학 공통 블록(한마디·2027 방식·연도 비교·준비 순서·자료의 한계)을 한 페이지에 몰아 싣지 않는다. 사용자 지시: "서울대 의대 면접 페이지, 수의대 등과 섞이지 말고".
- `lib/gichul-data/<key>.json` 의 `byField.<계열>` 에 그 계열 몫만 쓴다. 키가 있으면 그 페이지는 공통 블록 대신 이것을 싣고, `byField` 가 있는 대학은 공통 블록을 어느 페이지에도 싣지 않는다(`_univ-gichul.tsx` `blocksFor`). 출처도 `fields` 로 계열을 지정할 수 있다.
- `structure`(면접 구조)는 **요강·공식 자료와 후기·언론 기고를 열로 나눠** 적는다. 사교육 업체 기고·응시 후기는 공식 사실처럼 쓰지 않는다(서울대: 방 5개·방별 시간·추가 제시문은 지역내일 2026.9 소도스카이 기고, '빨간불 횡단보도'는 2014 CBS 응시자 회고).
